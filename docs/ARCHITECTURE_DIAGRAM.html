Kiến trúc hệ thống G4

Sàn thương mại điện tử kiểu eBay · ASP.NET Core 8 · SQL Server · vẽ từ source tại commit 7c25f74

1. Tổng quan thành phần

Đọc từ trái sang phải theo đường đi của request: trình duyệt → frontend (MVC, proxy) → G4.Api. Riêng kết nối realtime SignalR đi thẳng tới API. Trong khung G4.Api, các hàng xếp theo tầng: hàng trên gọi hàng dưới. Dữ liệu nằm bên phải, dịch vụ ngoài nằm bên dưới.

- - - Nét đứt: gọi HTTP / SQL / SMTP · · · Nét chấm: realtime SignalR

2. Các project trong solution

Mũi tên là ProjectReference. Domain và Contracts không phụ thuộc gì; Application chỉ khai báo interface; Infrastructure triển khai chúng. Api và Infrastructure cũng tham chiếu thẳng Contracts/Domain (không vẽ để đỡ rối).

3. Luồng realtime và thông báo

5. Cách triển khai

docker-compose.yml chạy đầy đủ

browser ─▶ frontend :5000 ─▶ backend :8080 browser ─▶ backend :8080 (SignalR) backend ─▶ sqlserver :14333→1433 backend ─▶ mailhog :1025 / :8025 backend ─▶ backend (Carrier__BaseUrl)
  • Mạng chung g4-net, volume sql_data
  • Frontend là proxy tin cậy của API (TrustedProxies)

docker-compose.nginx.yml demo cân bằng tải

nginx 127.0.0.1:8088 ├─ GET /api/catalog/random ─▶ api-a | api-b ├─ POST /api/auth/login ─▶ api-a └─ còn lại ─▶ 404 api-a, api-b ─▶ sqlserver (G4_Demo)
  • Catalog: round-robin, lỗi thì thử máy còn lại 1 lần
  • Worker tắt, email ở chế độ Capture

6. Nguyên tắc xuyên suốt

Quyền ở server

  • Role và user ID lấy từ JWT, không tin header client
  • Controller kiểm tra quyền sở hữu đơn trước khi gọi service

Đồng thời & tiền

  • UPDATE có điều kiện cho tồn kho
  • Khóa dòng / khóa theo tên + transaction Serializable
  • Idempotency key có unique index

Provider không chắc chắn

  • Lỗi mạng → Verifying, không giả Succeeded
  • Worker hỏi lại provider rồi mới retry
